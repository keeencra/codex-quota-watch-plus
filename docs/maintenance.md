# 长期维护计划

生效日期：2026-09-12。项目：码伴 · CodeCompanion（原 Codex Quota Watch Plus）。

## 维护范围

- Mac 服务与 HTTPS 外网连接、iPhone / Apple Watch 同步和 iPhone 小组件数据一致性。
- Codex 项目分组、任务标题、任务状态和带项目／任务名称的完成通知。
- 手表远程审批：请求来源、有效期、逐项批准／拒绝及结果回传；不得绕过 Codex 自身审批。
- Plus / Pro 与实际额度窗口显示、系统兼容性、现有自动续签。
- GitHub 介绍、真实界面展示、版本日志、固定下载渠道和上游许可证。

## 维护节奏

每周一北京时间 10:00 在现有任务检查一次；用户反馈随时处理。先比较上次本地维护记录、工作区和 GitHub 状态，再检查变化涉及的服务、测试、问题及发布入口。正常或同一非紧急问题未变化时保持安静；发现重要故障、完成修复或需要账号／设备操作时才通知。已有自动续签任务继续负责签名有效期与安装，不重复安排。

周检与自动续签共用同一个自动任务：每天北京时间 10:00、20:00 检查签名，仅周一 10:00 额外执行周检，不重复安装。

## 修复与发布

1. 先复现并记录触发条件、影响范围和预期行为，再做最小必要修复。不得覆盖用户未提交修改。
2. 根据改动运行 Python / Swift 检查；界面改动增加 Xcode 构建。不能把编译、模拟器或推送服务器接收当作真机验证。
3. 涉及真机时保留配对和应用数据。账号确认、设备信任或设备未连接时明确所需操作，不重置应用或设备。
4. 界面改动按 [配图规范](../AGENTS.md#更新日志配图)增加前后截图或标注清楚的示意图。按 AGENTS.md 同步 GitHub、CHANGELOG、版本索引、下载和 Release；无变化不发版本。新增产品功能／行为为大更新，仅修产品 Bug 为小更新；日志、配图等文档补充不升版本、不增加迭代，更新所属版本的说明即可。
5. 发布前检查公开仓库差异和敏感信息；不得上传运行配置、签名、密钥、设备标识、真实任务和审批详情。私有部署标识不得被公开示例替换。
6. 完成后记录实际验证、未验证部分、对应版本及后续行动。新增功能先依据用户需求形成具体方案，不自动扩大范围。
